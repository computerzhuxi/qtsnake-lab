1. 项目总体规划
    - 时机：在你创建第一个 .cpp 文件之前，花 30-60 分钟写一份简短的 docs/plan.md（或就叫“总体设计”）。
    - 内容（只抓骨架，不写详细细节）：
      - 项目最终形态：哪些模式（单人、AI、联机、回放）
      - 模块划分：core、ui、controller、ai、network、replay，各模块职责一句话
      - 核心流程：游戏主循环的大体流程（输入→更新→渲染），以及各模式如何复用同一套核心
      - 关键技术选型：为什么用 Qt5 Widgets 而非 Qt Quick、为什么用 QGraphicsView、为什么联机用 QTcpServer、AI 用 BFS 等（只写结论和一句话理由）
      - 依赖关系图（手绘草图或 Mermaid 均乐见）
   - 作用：这是你整个项目的“宪法”，后续所有里程碑微型文档都对齐它。面试时也能证明你具备“先设计再动手”的工程习惯。

2.  里程碑微型文档
    - 时机：比如你要开始做“AI 对战模式”，开工前先写一份小笔记。
    - 内容：只回答三问（做什么、怎么做、为什么这样做）。
    - 作用：把总体规划中的抽象模块落地为具体任务，保持思路连贯。

3. 头文件注释
   - 时机：声明类/函数的同时写 /// \brief ...。
   - 作用：保证接口清晰，面试时头文件就是最好的设计文档。
  
4. 测试用例
   - 时机：核心逻辑、AI、协议一完成就写。
   - 作用：验证功能正确，并作为永久的行为规格。 

5. docs/architecture.md  
   - 时机：通常在你的开发完成约 70% 时（比如联机模块刚调通），此时实际架构已经定型。
   - 内容：最终的架构图 + 关键决策回顾（可以基于 plan.md 更新）。
   - 作用：对外展示的深度材料。

6. README.md
   - 时机：开始就放一句介绍和构建依赖；全部功能完成后补上截图、GIF、操作指南。
   - 作用：项目门面。
